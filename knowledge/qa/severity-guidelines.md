# Bug severity guidelines (sample — replace with your team's)

- **Critical**: crash, data loss, security hole, or a core flow (login, checkout, payment) is completely blocked. No workaround.
- **Major**: a main feature is broken or gives wrong results, but a workaround exists.
- **Minor**: a secondary feature misbehaves, or a cosmetic issue that affects usability (misaligned button, unclear error).
- **Trivial**: typos, small visual polish, no impact on use.

Priority is set by the product owner, not the tester. Testers only set severity.
